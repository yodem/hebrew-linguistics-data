# ניקוד מול טעמי המקרא ביוניקוד

הבלוק העברי ביוניקוד הוא U+0590–U+05FF. הוא מערבב באותו טווח שלושה סוגי תווים: אותיות (U+05D0–U+05EA ועוד), סימני פיסוק (מקף, פסק, סוף פסוק) וסימנים מצרפים (combining marks) שהם הניקוד והטעמים. אין קטגוריה אחת בשם "ניקוד": ההבחנה נעשית לפי טווחי קוד, ובשלושה מקרים (מתג, רפה, מקף) הטווחים אינם נקיים. הטבלאות כאן נבדקו מול `unicodedata` של פייתון (שם התו, קטגוריה כללית ו-combining class), לא מהזיכרון.

## ההבחנות שחשוב לשנן

- **טעמים: U+0591–U+05AF, ורק הם.** כל התווים האלה Mn ובעלי combining class של 220–230 (מתחת, מעל, ויש גם 222 ו-228). כל הניקוד הרגיל נמצא ב-class נמוך (10–26), ומכאן הסדר הקנוני בהמשך.
- **ניקוד: U+05B0–U+05BC, U+05C1–U+05C2, U+05C7.** חבילה זו כוללת גם את הדגש.
- **המתג (U+05BD) הוא מקרה ביניים.** לפי קטגוריה הוא ניקוד (class 22), לפי תפקיד הוא סימן הטעמה מסורתי: מתג במקרא מוטעם, וגם סילוק (silluq) מקודד כ-U+05BD. בסידורים ובטקסט מנוקד בלי טעמים המתג (המכונה גם געיה) נפוץ ומסמן הטעמה משנית, ולכן ברירת המחדל כאן שומרת אותו (ראו להלן).
- **המקף (U+05BE), הפסק (U+05C0), סוף פסוק (U+05C3) ונון הפוכה (U+05C6) הם פיסוק, לא מצרפים.** regex של "הסר את כל הסימנים המצרפים" לא ייגע בהם, והם אינם בטווח הטעמים. לכן ההכרעה לגביהם היא סגנונית (טיפוגרפית), לא טכנית.
- **U+05BF (רפה)** הוא ניקוד לפי הקטגוריה (Mn, class 23), וכמעט תמיד מופיע רק בתנ"ך מוטעם או ביידיש (פ̄). אל תסתמכו עליו בעברית מודרנית.

## כלל פרקטי: להסיר טעמים ולהשאיר ניקוד

הרגקס הבסיסי: `[\u0591-\u05AF]`. כך נשמר כל הניקוד (U+05B0 ומעלה), כולל הדגש ונקודות השין. על שאר הסימנים כדאי להכריע כך (ברירת מחדל לטקסט מנוקד למטרות קריאה):

| סימן | ברירת מחדל | נימוק |
|---|---|---|
| מתג U+05BD | נשמר | טווח הניקוד; בלעדיו נשבר סימון הטעמה בסידורים ובטקסט הנקדני. לטקסט "נקי לגמרי" הסירו אותו |
| מקף U+05BE | נשמר | פיסוק עברי רגיל (בית־ספר); מחיקה תדביק מילים |
| סוף פסוק U+05C3 | נשמר | פיסוק מקובל בציטוט מקראי; החליפו ל-`:` רק אם המדיה דורשת |
| פסק U+05C0 | מוסר | פסק הוא סימן טעמים לכל דבר ואין לו תפקיד בטקסט בלי טעמים |
| נון הפוכה U+05C6 | מוסר | סימן מסורה בכתבי יד ובמהדורות מדעיות |
| נקודות עליונה ותחתונה U+05C4/U+05C5 | מוסרות | סימני מסורה (נקודות מעל ומתחת, puncta extraordinaria) |
| עיגול מסורה U+05AF | מוסר | כבר בטווח הטעמים |

### קוד (בדוק)

```python
import re
import unicodedata as ud

TEAMIM = "\u0591-\u05AF"                    # accents + masora circle
NIKUD = "\u05B0-\u05BC\u05C1\u05C2\u05C7"   # sheva..qubuts, dagesh, shin/sin dots, qamats qatan
METEG, RAFE = "\u05BD", "\u05BF"
PASEQ, SOF_PASUQ, NUN_HAF = "\u05C0", "\u05C3", "\u05C6"
UPPER_LOWER_DOT = "\u05C4\u05C5"

def strip_teamim(text, *, keep_meteg=True, keep_sof_pasuq=True,
                 drop_paseq=True, drop_nun_hafukha=True, drop_dots=True,
                 nfc=True):
    """Remove cantillation, keep vowel points (and by default meteg, maqaf, sof pasuq)."""
    t = ud.normalize("NFD", text)           # decompose U+FB1D..FB4E first
    drop = TEAMIM + ("" if keep_meteg else METEG) + (PASEQ if drop_paseq else "") \
         + ("" if keep_sof_pasuq else SOF_PASUQ) + (NUN_HAF if drop_nun_hafukha else "") \
         + (UPPER_LOWER_DOT if drop_dots else "")
    t = re.sub("[" + drop + "]", "", t)
    return ud.normalize("NFC", t) if nfc else t

def strip_nikud(text, *, teamim=False, meteg=True, rafe=True, nfc=True):
    """Remove points (and optionally te'amim), keep letters and punctuation."""
    t = ud.normalize("NFD", text)
    drop = NIKUD + (METEG if meteg else "") + (RAFE if rafe else "") \
         + (TEAMIM if teamim else "")
    t = re.sub("[" + drop + "]", "", t)
    return ud.normalize("NFC", t) if nfc else t
```

ברירות המחדל של `strip_teamim` תואמות לטבלה: שומרות מתג, מקף וסוף פסוק, ומסירות פסק, נון הפוכה ונקודות מסורה. בדיקה על "בְּרֵאשִׁ֖ית בָּרָ֣א אֱלֹהִ֑ים׃ וַֽיְהִי־אוֹר":

- `strip_teamim(s)` מחזיר `בְּרֵאשִׁית בָּרָא אֱלֹהִים׃ וַֽיְהִי־אוֹר` (המתג, המקף וסוף הפסוק נשארו).
- `strip_teamim(s, keep_meteg=False)` מחזיר את אותו הטקסט בלי המתג: `…וַיְהִי־אוֹר`.

## הכלל ההפוך: להסיר ניקוד ולהשאיר טעמים

במקרה הנדיר שבו רוצים טקסט עם טעמים בלבד (למשל חיפוש לפי הטעמים), הרגקס הוא `[\u05B0-\u05BC\u05C1\u05C2\u05C7]`, ואליו מוסיפים U+05BD (מתג) ו-U+05BF (רפה); הקוד מוסיף אותם כברירת מחדל. כך הטעמים נשארים על האות בלי הניקוד:

- `strip_nikud(s)` מחזיר `בראש֖ית בר֣א אלה֑ים׃ ויהי־אור` (נשארו הטעמים, המקף וסוף הפסוק; המתג והרפה הוסרו).
- `strip_nikud(s, teamim=True)` מחזיר `בראשית ברא אלהים׃ ויהי־אור`: אותיות עם פיסוק בלבד. בדיקה: `strip_nikud(s, teamim=True) == strip_teamim(strip_nikud(s))` נותן True.

**נקודות שין:** `strip_nikud` מסיר גם את U+05C1/U+05C2 והופך שׁ ו-שׂ ל-ש. זה רצוי לחיפוש ולהשוואה, אבל לא לטקסט שבו ההבחנה בין שׁ ל-שׂ היא חלק מהקריאה (שׁיר/שׂיר). אם צריך לשמור אותן, הסירו את U+05C1 ו-U+05C2 מהקבוע `NIKUD`.

## צורות ההצגה U+FB1D–U+FB4F: למה לנרמל לפני הרגקס

בלוק צורות ההצגה האלפביתיות מכיל אותיות עם ניקוד כתו יחיד. רגקס שמחפש רק מצרפים לא יראה את הניקוד שבתוכן: בדיקה על `"\uFB2A\u05B8\uFB1D"` עם `re.sub("[\u05B0-\u05BC]", "", p)` מחזירה אותו טקסט בלי שינוי, כי U+FB2A (שׁ) ו-U+FB1D (יִ) הם Lo ולא Mn. לכן יש לבצע `NFD` לפני ההסרה. אחרי NFD הם מתפרקים: FB2A ל-05E9 05C1, FB1D ל-05D9 05B4. אחרי `strip_nikud` נותרות רק האותיות 05E9 ו-05D9.

חריגים: הצורות U+FB20–U+FB28 (אותיות רחבות) ו-U+FB4F (ליגטורת אלף־למד) הן צורות תאימות (compat) ו-NFD אינו מפרק אותן; רק NFKD/NFKC עושה זאת. אם הקלט עשוי להכיל אותן, השתמשו ב-NFKD, אך שימו לב שהוא משנה גם תווים אחרים (למשל ליגטורות לטיניות).

## נרמול וסדר הסימנים (המלכודות)

1. **הסדר הקנוני נקבע לפי combining class.** NFC/NFD ממיינים רצף של סימנים מצרפים על אות אחת לפי הערך העולה. מכיוון שניקוד הוא class 10–26 וטעמים הם 220–230, אחרי נרמול הניקוד תמיד לפני הטעם. הדגש (class 21) מתמיין אחרי התנועות (10–20), ואחריו מתג (22), רפה (23), נקודת שין (24) ונקודת שׂין (25). בדיקה: `NFC("\u05E9\u05C1\u05BC\u05B8")` (שין, נקודת שין, דגש, קמץ) מחזיר `05E9 05B8 05BC 05C1`, כלומר קמץ, דגש, נקודת שין.
2. **לכן הסדר "אות + דגש + תנועה" והסדר "אות + תנועה + דגש" שקולים בנרמול, אבל לא בהשוואת מחרוזות גולמית.** השוו תמיד אחרי NFC או NFD, ולא לפני. לחיפוש בטקסט מנוקד נרמלו את השאילתה ואת הקורפוס באותה צורה.
3. **NFC לא מאחד לצורות ההצגה.** צורות U+FB1D–U+FB4E מוחרגות מהרכבה (composition exclusion): בדיקה `NFC("\u05D9\u05B4") == "\uFB1D"` מחזירה False. לכן NFC הוא בטוח כצורה סופית, ומסמך שנכתב עם U+FB1D ישוטח ל-U+05D9 U+05B4 אחרי נרמול (וזה הרצוי).
4. **סדר הפעולות בקוד:** הפונקציות לעיל מבצעות NFD לפני ההסרה, ומסיימות ב-NFC כברירת מחדל (`nfc=False` מחזיר את צורת הפירוק). נרמלו לפני עימוד ולפני השוואה.
5. **מניעת מיון: CGJ.** לפעמים צריך לשמור סדר שאינו קנוני בין סימנים; לשם כך מציבים בין הסימנים את U+034F (COMBINING GRAPHEME JOINER). זה משנה את תוכן המחרוזת (תו נוסף), ולכן אין להשאיר אותו בטקסט שאמור להיות "נקי".

## הסתייגויות

- זהו כלל על קודי יוניקוד ולא על הלשון: האקדמיה ללשון אינה קובעת מה "ניקוד" ומה "טעם" ברמת התווים. ההכרעות במתג, בפסק ובסוף פסוק הן הנחיית עריכה, לא חובה יוניקודית.
- מתג וסילוק (silluq) מקודדים באותו תו, U+05BD: ביוניקוד אין הבחנה בין שני התפקידים, וכל הבחנה ביניהם דורשת ניתוח לפי מקום בפסוק ולא לפי תו.
- גרסת יוניקוד: הנתונים לעיל נבדקו בגרסה 13.0 של `unicodedata` בפייתון 3.9. לא נבדקו גרסאות אחרות; מומלץ להריץ מחדש את הבדיקות בסביבת היעד.
- הפונקציות לעיל אינן מטפלות בשגיאות קלט (טקסט חצוי באמצע אות, סימנים מצרפים ללא אות בסיס) ומניחות שהטקסט כבר פוענח כ-UTF-8.
